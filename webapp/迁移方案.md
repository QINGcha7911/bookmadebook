## 2. 数据库选型结论

| 方案 | 成本 | 公网直连（daemon） | 结论 |
|---|---|---|---|
| **Tablestore 表格存储（按量）** | 无实例月费，按读写 CU 计费（量小≈几元/月量级；免费额度以控制台为准） | ✅ 实例自带公网 endpoint | ✅ **推荐** |
| RDS MySQL 基础版 | ~¥50-100/月固定（1C 1G 起步），个人产品不划算 | ✅ 需开公网地址（另计流量/安全组） | ❌ 贵且重 |
| FC 内置 SQLite（/tmp） | 0 | ❌ /tmp 不持久（实例回收即丢），FC 无状态 | ❌ 不可用 |
| FC + OSS（JSON 文件当库） | 极低 | ❌ 要自己实现并发/一致性，状态机难做 | ❌ 工程量大 |

**为什么 Tablestore**：
- 按量模式免实例费、免运维，个人可开通（阿里云控制台搜索「表格存储」）；
- 天然 KV + 单行主键，订单按 `id` 点查/更新（`get`/`patch`）就是主键读写，语义与 D1 完全对齐；
- 支持原子自增（限流计数）、条件写（幂等/状态校验），足以复刻现有业务；
- daemon 从你电脑 30s 轮询走**公网 endpoint** 直连，无需中转服务。

**代价（MVP 接受）**：无 SQL，`getPendingPaid()`（按 status 过滤）只能全表 `getRange` 后内存过滤。
当前量级（每天几十单、全表几百行）30s 轮询毫无压力；**量大后再加「paid 队列表」**（daemon 改为范围读队列表，见 §7 TODO）。

### 2.1 Tablestore 表设计（与 D1 schema 对照）

实例建议与 FC 同地域 `cn-hongkong`（函数走内网更省；daemon 走公网）。

**表 1：`orders`**（主键 `id` STRING，一行一单；属性列 = D1 orders 全字段，`null` 不写、读回补 `null`）

| OTS 列 | 类型 | 对应 D1 | 说明 |
|---|---|---|---|
| `id`（PK） | STRING | id TEXT PK | 订单号 BM-XXX |
| `email` | STRING | email | 限流键之一 |
| `product_type` | STRING | product_type | adult / child |
| `book_title` | STRING | book_title | |
| `book_id` | STRING | book_id | 儿童白名单 id（成人无） |
| `duration_min` | INTEGER(Long) | duration_min | |
| `voice` | STRING | voice | |
| `age_band` | STRING | age_band | 3-6 / 7-12 |
| `parent_declared` | INTEGER(Long) | parent_declared | 1/0 |
| `amount_fen` | INTEGER(Long) | amount_fen | |
| `status` | STRING | status | 状态机字段 |
| `provider` | STRING | provider | 支付渠道 |
| `voucher` | STRING | voucher | 支付凭证 |
| `oss_key` | STRING | oss_key（任务 4 新增） | OSS 对象 key：orders/{id}.mp3（daemon 上传后写入，签名的依据） |
| `eta_min` | INTEGER(Long) | eta_min | |
| `created_day` | STRING | created_day | 限流键之一 |
| `created_at` | STRING | created_at | ISO8601 |
| `updated_at` | STRING | updated_at | |

**表 2：`rate_limits`**（主键 `key` STRING = `${email}#${created_day}`；属性列 `count` INTEGER）
- 解决「每邮箱每日 3 单」：`todayCount` 读该行 count；下单成功 `insert` 时对 count 做**原子 INCREMENT +1**（首单条件建行=1），避免并发下查-增竞态。
- 语义与 D1 版略有差异（D1 是 count 订单行）：计数只增不减，防滥用足够；退款/删单不影响计数，**更保守**（偏严可接受）。

## 4. 部署步骤（008 控制台操作清单）

### A. 一次性准备（控制台）
1. **开通函数计算 FC 3.0**：选地域 **cn-hongkong**（中国香港，自定义域名**免 ICP 备案**；大陆地域要备案，见坑 2）。
2. **开通表格存储 Tablestore**（按量计费），同地域创建实例（如 `bookmadebook`）。记下实例名。
3. **建表**（二选一）：
   - 控制台 → 实例 → 数据管理 → 创建表（按 §2.1 两表结构）；
   - 或本机跑 `node fc/schema.ots.mjs`（需配好下面 AK 环境变量，且本机能访问 OTS 公网）。
4. **RAM 最小权限子账号 AK**（避免用主账号）：
   - 策略 1：`AliyunFCFullAccess`（部署 FC）——也可只在 s 配置里用；
   - 策略 2：`AliyunOTSFullAccess` 或更小 `ots:GetRow/PutRow/UpdateRow/GetRange/...`（函数运行时读表）；
   - 建议两个子账号或一个账号两把 AK 分开用途，最小暴露。
5. **域名**：准备一个域名（如 `book.xxx.com`），阿里云 DNS 解析到 FC 自定义域名后给出的 CNAME 目标。

### B. 本地配置 + 部署（008 在有 node 的机器）

## 5. 坑清单（部署必读）

1. **fcapp.run 默认域名强制下载 ⚠️ 最重要**：FC 3.0 默认 HTTP 触发器域名（`{随机}.{region}.fcapp.run`）对响应强制加 `Content-Disposition: attachment` 且**不可修改**——浏览器打开会下载 HTML/JSON 而不是渲染。官方明确该域名仅供测试、禁止生产。**生产必须绑自定义域名**（绑定后解除强制下载）。API 侧（daemon）不受影响，联调可直接用默认域名。
2. **ICP 备案**：自定义域名绑**中国大陆地域** FC 需要 ICP 备案；**中国香港/海外地域免备案**。因此建议函数+OTS 都建在 `cn-hongkong`。008 部署时以阿里云控制台当前提示为准。
3. **/tmp 不持久**：FC 实例的 `/tmp` 随实例回收清空，禁止当数据库/产物存储。订单数据全在 Tablestore，mp3 全在 OSS（任务 4 已实现直传+签名下载）。
4. **Tablestore 公网流量计费**：daemon 从本地轮询必走公网 endpoint（量小：每次拉单+状态更新几 KB，月费可忽略）。函数与 OTS 同地域时，008 可尝试在函数侧配**内网/VPC endpoint** 进一步降费（若配置复杂，MVP 直接都走公网即可）。
5. **FC event 不是 Node req/res**：FC 3.0 是结构化 event（`requestContext.http.method/path`、`headers`、`queryParameters`、`body`+`isBase64Encoded`）。已由 `fc/index.mjs` 适配，勿在业务代码里假设 `req.url` 存在。
6. **响应头限制**：FC 会忽略 `content-length`/`date`/`server`/`content-disposition` 等头——不要在业务层依赖设置这些。CORS 头可正常返回（函数侧同源时基本用不到）。
7. **ESM 入口**：`fc/index.mjs` 用 `.mjs` + 具名导出 `handler`（s.yaml `handler: index.handler`）。若 008 部署时运行时不识别 `.mjs`，在 `fc/` 下加 `package.json`（`{"type":"module"}`）并把 `index.mjs` 改名 `index.js`，handler 配置不变。
8. **FC 超时/内存**：s.yaml 默认 256MB / 30s。订单 API 都是轻量 Tablestore 读写，足够；若 008 加「签名下载」等重逻辑再上调。
9. **限流窗口**：`todayCount` 先查后 `INCREMENT` 存在极小并发窗口（同一邮箱瞬间并发两单可能各放行一次）。防滥用场景可接受；若要严格，把「count < 3」条件写进 INCREMENT 的条件更新，失败即 429（下一轮可做）。
10. **免费额度以控制台为准**：FC 3.0 / Tablestore 的试用额度会随活动变化，方案里不做承诺；个人量级即便全按量付费也在几元/月量级。

11. **新 Tablestore 实例默认不开公网（403 真因）**（2026-09-06 实测）：香港容量型实例默认 Network ACL 只允许内网/VPC，daemon/本机从公网数据面访问一律报 `Request denied by instance ACL policies`——**此时不是 Instance Policy 问题**。需先开公网，CLI 最稳：
    ```bash
    aliyun tablestore UpdateInstance --region cn-hongkong \
      --InstanceName bookmadebook --NetworkTypeACL '["INTERNET","VPC","CLASSIC"]'
    ```
    ⚠️ 新版 API 是 **2020-12-09 + ROA 风格**（域名 `tablestore.cn-hongkong.aliyuncs.com`，POST /v2/openapi/updateinstance）；老版 2016-06-20 只有 ListInstance/GetInstance、**没有 UpdateInstance**。控制台实例详情也有公网开关，但 008 实测 CLI 更可靠。

12. **控制台实例策略 UI 有 bug（脚本模式锁死）**：可视化编辑只生成 `instance/*` 这类残缺 ARN → 保存报 Resource not found；「脚本模式」被锁死不可编辑。正确 Instance Policy 的 Resource 必须带**真实主账号 UID**：`acs:ots:*:<UID>:instance/bookmadebook*`（实例名可通配）。UI 卡住时用 CLI/API 配，或先按坑 11 开公网再回控制台补策略。

13. **rate_limits 表主键 bug（OTSInvalidPK）**（已修 commit 9aae491）：`rate_limits` 表主键列名是 `key`（不是 `id`），store-ots 曾误用 `pkOf`（列名 `id`）→ 限流读写全报 OTSInvalidPK（订单表能写、限流静默炸）。修复用 `pkOfKey`。日后加表先对照 `fc/schema.ots.mjs` 核对主键列名，别想当然用 `id`。

14. **FC3 nodejs 运行时 event 是 Buffer/字符串，不是结构化对象**（已修 commit 9aae491）：FC 3.0 nodejs20 HTTP 触发器实测 event 以 **Buffer** 传入 handler——本地 node 直调传对象不会暴露，「本地 200、线上全 index.html/行为异常」类诡异现象先怀疑这层。入口必须兼容：
    ```js
    let event = rawEvent;
    if (Buffer.isBuffer(rawEvent)) event = JSON.parse(rawEvent.toString('utf8'));
    else if (typeof rawEvent === 'string') event = JSON.parse(rawEvent);
    ```
    已补单测（`test/fc-handler.test.mjs` 的 Buffer/string 分支）。

15. **s deploy 重部署会重置环境变量（控制台注入的 AK 会丢）**：s 以 yaml `environmentVariables` 整体覆盖函数配置——控制台手工注入的 `TABLESTORE_AK_ID/SECRET`、`OSS_AK_ID/SECRET` 不在 yaml 里，**重部署后即被清空**，函数表现为建 store 抛错/订单写不进 OTS/下载 URL 回落占位。解法：a) 重部署前从 FC 控制台现有配置复制 AK 回填 yaml（走 s 变量/本机环境引用，**勿明文提交**）；b) 或部署后立即回控制台重新注入并跑一遍验收（§4 E）。`webapp/` 根 `s-fc-deploy.yaml`（code=./deploy 自包含）与 `fc/s.yaml` 两套模板都适用此坑。

## 5.1 OSS 音频交付设计（任务 4 已实现）

**链路**：daemon 直传（不经 FC，mp3≈9MB 超 FC HTTP 触发器请求体限制）→ 订单行存 `oss_key`
→ 用户查单时 FC 现场签 24h 临时下载 URL（防扩散盗链）。

| 项 | 设计 |
|---|---|
| Bucket | `bookmadebook-audio`（cn-hongkong，**私有读写**；建议开启服务端加密） |
| 对象 key | `orders/{order_id}.mp3`（daemon/FC 两侧约定一致，见 `oss_upload.py` / `oss.mjs`） |
| 上传方 | 本地 daemon（`daemon/oss_upload.py`，oss2 SDK）——直传不经 FC |
| 签名方 | FC（`fc/oss.mjs`，OSS V1 预签名，node:crypto 零依赖，无 OSS API 调用） |
| 有效期 | 24h（`Expires` 参数；前端轮询到 done 即得新链接，过期后重新查单会再签） |
| 权限最小化 | daemon AK 仅 `oss:PutObject`；FC AK 仅 `oss:GetObject`（签名虽不需调 API，仍按最小给） |
| 失败语义 | 上传重试 3 次（指数退避）仍失败 → PATCH failed（用户可见可退款），**不静默丢单** |
| 本地开发 | `BOOKMADE_OSS_MOCK=1` 模拟上传；FC 侧无 OSS env 时 download_url 回落占位（仅联调） |

**daemon 用 AK 最小权限策略建议**（008 建 RAM 用户时用）：
```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject"],
      "Resource": ["acs:oss:*:*:bookmadebook-audio/orders/*"]
    }
  ]
}
```
**FC 用 AK 最小权限策略建议**（签名 URL 生成本身不调 OSS API，此策略仅兜底未来直读/STS）：
```json
{
  "Version": "1",
  "Statement": [
    { "Effect": "Allow", "Action": ["oss:GetObject"],
      "Resource": ["acs:oss:*:*:bookmadebook-audio/orders/*"] }
  ]
}
```

**008 需开的 OSS 资源清单**：
1. OSS bucket `bookmadebook-audio`（地域 `cn-hongkong`，读写权限=私有，默认即私有）；
2. （可选）服务端加密 + 生命周期规则（旧 mp3 30 天后转低频/清理，按量省钱）；
3. RAM 两个子账号 AK 或一账号两 AK：daemon 上传（PutObject）/ FC 签名（GetObject）；
4. daemon 所在机器 `pip install oss2`；
5. FC 环境变量补 `OSS_BUCKET/OSS_REGION/OSS_AK_ID/OSS_AK_SECRET`；
6. daemon 环境变量补 `OSS_ENDPOINT/OSS_BUCKET/OSS_AK_ID/OSS_AK_SECRET`（可放 `webapp/daemon/.env`，已 gitignore）；
7. 无需配 CORS：下载是 `<a href>` 直开签名 URL，不跨域读。

**本地端到端验证（无真实 OSS）**：
```bash
cd webapp
BOOKMADE_OSS_MOCK=1 python3 daemon/daemon.py --once --mock-script   --base-url http://127.0.0.1:8787 --token dev-daemon-token-001
# 订单 PATCH done 会带 oss_key=orders/BM-XXX.mp3；FC 侧配 OSS env 后查单返回签名 URL
```
