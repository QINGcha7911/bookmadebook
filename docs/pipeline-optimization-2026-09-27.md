## 五、交付格式铁律（2026-09-27 新增 · 004 贴正文实测血泪）

> **讲书稿/文案等一切文本交付物，一律发【文件附件】（或飞书云文档链接），禁止只贴正文。**

原因（实测）：004 把 1,612 汉字的讲书稿**贴在消息正文**里，飞书卡片**压掉了换行** ——
007 从消息里切出的正文「以 ## 开头的行 = 0」，所有章标题被粘进上一行
（形如 `…口播字# 偶尔向生活请个假## 开场半夜醒来。`），且尾部疑似截断。
⇒ 这种稿件**不能进生产线**（章节切分会数错、TTS 会念错），只能退回重发，白等一轮。

标准交付格式：**文件附件（首选）｜飞书云文档链接（次选）**；消息正文只写「四行读数 + 文件名」。

## 六、BGM 自检三角验证与「读数为空 = 未跑」（2026-09-27 新增 · 双端实证）

背景：兜底 BGM 交付时，007 与 008 **各自**踩到同一类静默失败 —— 电平检查器永远解析不到数值，
却可能被当成「跑过了」。两边的成因不同、表现相同：

| 位置 | 错法 | 表现 |
|---|---|---|
| 007 侧 `bgm_loop_check.sh` | `ffmpeg -v error` 把 `volumedetect` 的日志一起吞掉 | 三个电平全为空字符串 |
| 008 侧 helper `mean_volume` | 漏写 `-af volumedetect` | 恒返回 -99（假失败，也可能掩盖假通过） |

**已修**：007 侧只改 volumedetect 那几行（ffprobe 行不动，改宽了会连带报 `-nostats` 不识别）；
008 侧加防护：**读数缺失或解码为空 ⇒ ok=False 且 note=INVALID_NO_READING**（已用不存在的文件实测 ✓）。

**规则（进入交付门禁）**：
1. 任何自检必须**能打印出数字**才算跑过；读数为空 / 恒值（如 -99）/ 解析失败 ⇒ **一律判未跑**，不得视为通过
2. 「跑过」的凭证 = 命令 + 输出读数 + 文件 md5，三者齐备
3. 交付类 BGM 自检须**双方法互证**（如 ffmpeg volumedetect 与 PCM s16le 直算 RMS）：
   本次两法对同一原曲读数 -15.2/-43.1/-75.0 与 -15.38/-43.15/-73.65 一致 ⇒ 结论可信 ✓
4. 素材库既有资产**不可假定合规**：本次实测 `bgm_ambient`(128k 单声道)、`bgm_piano_open`(192k/48k 单声道)
   均**不合交付规格**；`bgm_piano_close` 合规格但**原曲带淡入淡出**（首 -43.1 / 末 -75.0 dB）
   ⇒ 必须裁剪后才能作为循环友好交付件（裁后 161.75s，首末偏差 1.30 dB ✓）
