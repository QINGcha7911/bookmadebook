# listen-book Harness 架构方案

## 目标
把 listen-book 从"技能知识包"升级为"Harness 执行框架"——
每步强制校验，不通过就停止/回滚，杜绝注水、重复、标题朗读等问题。

## 核心思想：Harness = 知识 + 控制循环 + 验证门

```
┌─────────────────────────────────────────────────────────┐
│  HARNESS 控制循环（harness.py 主控）                      │
│                                                         │
│  [1. 输入校验] 书/时长/语言/风格 → 参数合法性检查          │
│      ↓ 通过                                              │
│  [2. 内容获取] book_info → 公版书/简介 → 生成讲书稿        │
│      ↓ 通过                                              │
│  [3. 内容质量门] 字数校验+重复检测+金句去重+版权检查        │
│      ✗ 不通过 → 报错停止（诚实告知）→ 可回滚换书/缩时长    │
│      ↓ 通过                                              │
│  [4. 分段生成] speed_probe语速 → TED导演层分段            │
│      ↓ 通过                                              │
│  [5. TTS合成] edge-tts逐段 → L2缓存                      │
│      ↓ 通过                                              │
│  [6. 拼接+BGM] concat → mix_bgm → L3缓存                 │
│      ↓ 通过                                              │
│  [7. 输出验证门] 开头无标题(波形相关) + 时长偏差≤10%       │
│      ✗ 不通过 → 自动重生成/报错                          │
│      ↓ 通过                                              │
│  [8. 交付] 输出mp3 + 元数据(json) + 章节标记              │
└─────────────────────────────────────────────────────────┘
```

## 与现有代码的映射

| Harness 阶段 | 现有组件 | 需要新增/强化 |
|-------------|---------|--------------|
| 1. 输入校验 | streaming_pipeline.py 参数 | 参数schema校验 |
| 2. 内容获取 | book_info.py / book_fetcher.py | 无 |
| 3. **内容质量门** | standard_mode.txt（规则）| **quality_gate.py 新脚本**（自动检测重复/金句去重/字数）|
| 4. 分段生成 | speed_probe.py + ted_director.py | 无 |
| 5. TTS合成 | streaming_pipeline.py generate_segment | 无 |
| 6. 拼接+BGM | streaming_pipeline.py + bgm_selector.py | 无 |
| 7. **输出验证门** | 手动波形相关自查（上次教训）| **output_verify.py 新脚本**（自动验证开头无标题+时长）|
| 8. 交付 | 已有 | 元数据json |

## 新增2个核心脚本

### 1. quality_gate.py（内容质量门）
```python
# 输入：讲书稿文本 + 目标时长
# 功能：
#  - 字数校验（实测语速 × 目标 = 需要字数，不足报错）
#  - 重复检测（n-gram 相似段落检测，重复>阈值报错）
#  - 金句去重（同一金句出现>1次报错）
#  - 标题/markdown残留检测（#开头行）
#  - 版权检查（现代书→无全文标志）
# 输出：通过/不通过 + 详细错误报告
```

### 2. output_verify.py（输出验证门）
```python
# 输入：生成的mp3 + 期望时长 + 标题对照
# 功能：
#  - 开头波形相关性检测（vs 标题朗读 → <0.1 干净）
#  - 时长偏差检测（±10%内）
#  - 音频完整性（时长>0、可解码）
# 输出：通过/不通过 + 报告
```

## 调用链改造

```
之前：streaming_pipeline.py 一条龙（内容不足只警告，继续生成）
之后：harness.py 主控
  → 调 quality_gate（不过→停）
  → 调 streaming_pipeline（生成）
  → 调 output_verify（不过→报告）
```

## 用户价值
1. **杜绝注水**：质量门强制，内容不足直接停（已部分实现）
2. **杜绝重复**：自动检测，不靠LLM自觉
3. **杜绝标题朗读**：输出验证门，自动测波形（上次的教训）
4. **可观测**：每步状态+日志，失败知道卡在哪
